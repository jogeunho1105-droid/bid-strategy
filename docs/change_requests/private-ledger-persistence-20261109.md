# 비공개 원장 영구 보관 및 자동 복구

## 요청과 변경 범위

사용자는 서버 재시작 뒤에도 새 원장이 유지되고 자동으로 불러와지도록 요청했다. 원장 데이터는 공개 저장소에 올리지 않고 추천식·가중치·화면·추천표·Excel 양식은 유지한다. 기존 수집 원본과 동결 원장도 변경하지 않는다.

원장 전용 `jogeunho1105-droid/bid-strategy-ledger-private` 저장소를 **비공개**로 생성했다. 검증된 운영 Excel을 SHA-256별 불변 경로 `versions/<sha256>.xlsx`에 보관한다. `latest.json`은 활성 파일 경로·크기·해시·데이터 버전만 담는다. 이전 파일은 덮어쓰지 않으며, 활성 포인터도 GitHub 커밋 이력에 남는다. 공개 앱 저장소에는 복구 코드·설정 예시·집계 검증 결과만 둔다.

자동 복구는 로컬 `history.pkl`이 없을 때 실행된다. 처음 비공개 저장소를 연결할 때도 앱 전용 키가 실제 작동하는지 확인하기 위해 한 번 다운로드·검증하고, 기존 로컬 원장을 백업한 뒤 적용한다. 이후에는 복구 확인 파일과 로컬 이력이 있으면 로컬 캐시를 사용한다. 인증된 GitHub API로 저장소 비공개 상태, 포인터 형식, 파일 크기·SHA-256, Excel 내부 원장 내용 해시·행수·출처 행수를 검증한다. 검증을 통과한 전체 운영 원장으로 기존 `save_history`와 동일한 정제 과정을 실행한다. 원천행 출처·분류확인·품질 상태도 복구한다. 복구 확인 파일에는 저장소명과 데이터 버전만 담으며 키는 저장하지 않는다.

관리자 신규 업로드는 기존 내용 검증 → 비공개 불변 파일 저장 → 재다운로드 해시 확인 → 활성 포인터 변경 → 로컬 적용 순서다. 원격 저장 실패나 동시 포인터 충돌 시 기존 원장을 유지한다. 비공개 저장소가 공개로 바뀌면 데이터 읽기·쓰기를 중단한다. 로컬 파일은 임시 파일을 완성한 후 교체하여 쓰기 중단으로 이전 파일이 깨지는 것을 방지한다. 추천 코드와 화면 코드는 변경하지 않는다.

## 앱 전용 연결 설정 — 사용자 직접 진행

공개 저장소에 인증값을 넣지 않으므로 Streamlit의 비공개 Secrets에 앱 전용 키를 한 번 등록해야 한다. GitHub 계정 전체 권한의 기존 로그인 키를 앱에 복사하지 않는다.

1. GitHub의 [Fine-grained token 생성](https://github.com/settings/personal-access-tokens/new?name=bid-ledger-streamlit&target_name=jogeunho1105-droid&contents=write&expires_in=366) 화면에서 로그인한다.
2. **Repository access → Only select repositories**를 선택하고 **bid-strategy-ledger-private 하나만** 선택한다.
3. **Repository permissions → Contents: Read and write**를 선택한다. Metadata 읽기 외에 다른 권한은 추가하지 않는다. 발급은 계정 소유자가 직접 한다. 만료일 전 갱신이 필요하다.
4. [Streamlit 관리](https://share.streamlit.io/)에서 로그인하고 기존 `bid-strategy` 앱의 **Settings → Secrets**를 연다.
5. 기존 관리자 설정을 보존하고 다음 구역을 추가한다. 실제 키는 채팅·공개 Git에 보내지 말고 Streamlit 설정에 직접 붙여넣는다.

```toml
[ledger_store]
repository = "jogeunho1105-droid/bid-strategy-ledger-private"
branch = "main"
token = "여기에 앱 전용 키를 직접 입력"
```

6. Save 후 설정 완료를 알리면 실제 재부팅·자동 복구·샘플 추천·두 Excel 다운로드를 확인한다. 키 미설정 상태에서는 기존 로컬 업로드 동작을 유지하며, 자동 복구가 운영에서 완료됐다고 보고하지 않는다.

설정 예시는 [.streamlit/secrets.example.toml](../../.streamlit/secrets.example.toml)에 있다. 키가 만료되거나 취소되면 원격 복구·저장이 차단되므로 Secrets에서 새 앱 전용 키로 교체한다. 이미 복구된 로컬 이력은 계속 사용할 수 있다.

공식 근거: [Streamlit 비공개 Secrets 관리](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management), [GitHub 최소 권한 토큰](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens), [GitHub Contents API](https://docs.github.com/en/rest/repos/contents).

## 검증 현황

- 비공개 저장소 익명 접근: HTTP 404.
- 현재 원장 Excel 38,372,650바이트, SHA-256 `04b9e047ba9d0311907057ac875134c05a4c2c84232d01759560a78d463a607f` 저장 후 재다운로드 검증 완료.
- 빈 로컬 폴더 자동 복구: 운영 112,572건, 학습 91,259건, 버전 `collection-20261109-supervision-8482` 일치. 운영 원장 내용 해시·전체 학습 입력·출처·분류확인 복구 검사 통과.
- 자동 회귀검사 151개 통과, 실패·오류·건너뜀 0개. 저장소에 없는 과거 분석 모듈 4개를 참조하는 기존 `test_v2_15_6`은 이전과 같이 제외했다.
- 운영과 같은 Streamlit 1.40.2 / pandas 2.3.3 / numpy 2.5.4 환경의 실제 앱 실행 검사에서 빈 서버 폴더 → 인증 다운로드 → 원장 복구 → 샘플 4건 추천표 → 버전 표시를 확인했다. 앱 예외 0개다.
- 앱의 함수 84개는 구문 단위로 이전 커밋과 동일하다. 달라진 함수는 원장 읽기·저장·품질 정보 읽기 3개뿐이며, 관리자 업로드 분기에 비공개 저장 호출을 추가했다. 추천·금액·업체수·표·Excel 함수는 동일하다. 쓰기 도중 중단돼 품질 정보만 이전 버전에 남은 경우 전체 운영 원장으로 다시 계산해 버전 혼선을 방지한다.
- 사용자가 운영 Secrets 등록을 완료했고, 전체 rolling 비교 통과 후 배포했다. 실제 앱 전용 키로 초기 복구·서버 재부팅 검증도 완료했다. 세부 결과는 아래에 기록한다.
- 최종 앱 원격 복구 검사 중 한 번 연결 실패가 있었고 재검사에서는 정상 복구·추천표 생성까지 통과했다. 읽기 요청의 일시적 통신 오류·429/5xx는 최대 3회로 제한해 재시도한다. 결과가 불확실한 쓰기 요청은 자동 반복하지 않는다. 권한·무결성 오류는 보류하고 기존 원장을 유지한다.

# 비공개 전략결과 게시 화면 (2026-10-22)

## 범위
- `pages/01_게시된_투찰전략.py`를 추가한다. 기존 진입점 `입찰 앱.py`, 추천엔진, 참여수 규칙, 낙찰원장, 의존성 목록은 변경하지 않는다.
- 이 화면은 **완성된 검토안**을 표시하는 기능이다. 입찰서류함을 분석하거나 낙찰원장을 갱신하지 않는다.
- 로그인된 관리자 브라우저에서 게시용 Excel을 한 번 올려야 한다. 기능코드의 배포만으로 자료가 게시되는 것은 아니다.

## 접근 및 게시
1. 사이트 왼쪽 페이지 선택에서 `게시된 투찰전략`을 선택한다.
2. Streamlit Secrets에 설정된 `ADMIN_PWD`로 인증한다. 없거나 이전 기본값이면 닫힌 상태로 중단한다. 비밀번호를 채팅이나 저장소에 넣지 않는다.
3. 완성된 `YYYYMMDD_...검토안...xlsx`를 올려 미리보기를 확인하고 체크 후 `검증 후 게시`를 누른다.
4. 저장 후 해시와 행수를 재확인한 원본만 표와 다운로드로 표시한다. 원본은 재작성하지 않는다.

## 보호기준
- 인증 전에는 업로드, 저장목록, 사정률표, 다운로드를 만들지 않는다.
- XLSX 10MB/해제 40MB, 최대 500 공고, 2,000행/100열 한도. 매크로, 잘못된 셀주소, XML DTD, 요약수식, 잘못된 사정률과 하한율을 거부한다.
- 공동주택 감리의 업체2/3 숫자 추천값은 차단한다. 수집 및 분석모형 자체의 변경은 별도 작업이다.
- 보류표기는 원본 그대로 유지한다. 파일명 분석일과 제목 분석일이 일치해야 한다. 과거 분석일은 오늘 결과로 표시하지 않는다.
- 서버 `data/private_publications`에 해시별로 버전을 저장한다. 동일 파일은 중복 게시하지 않고 기존 파일은 덮어쓰지 않는다. 잠금·임시저장·원본해시·저장 후 검사 적용.
- 이 저장은 Community Cloud의 영구 저장을 보장하지 않는다. 원본은 회사 비공개 OneDrive에 유지하고 서버 재생성 때 다시 업로드한다. 자동 OneDrive 연동·예약실행은 추가하지 않았다.
- 공개 GitHub에는 이 코드와 합성자료 테스트만 보관한다. 실제 공고별 추천값, Excel, 원장, 비밀번호는 넣지 않는다.

## 검증
- Python 문법검사 및 합성자료·인증·파일보호 단위검사 23건 통과.
- 로컬에서 제공받은 수정본 8건 읽기와 구버전 다중참여 차단을 별도로 검사했으며 해당 파일은 공개 저장소에 포함하지 않았다.
- 로컬 환경에 Streamlit이 없어 Streamlit UI 실행검사와 실서버 로그인·업로드는 미실시. GitHub 반영, Streamlit 구동, 실제 자료 게시 완료는 각각 별도로 확인해야 한다.

## 되돌리기
추가한 게시페이지를 제거하면 기존 단일페이지 동작으로 돌아간다. 서버 결과폴더나 원장은 자동 삭제하지 않는다.

# 투찰전략 분석 시스템 v2.15.7

낙찰이력과 공고의 발주기관·업종·참여조건을 바탕으로, 당사가 참여할 수 있는 1~3개 업체의 최종 추천 사정률과 추천기준금액을 제공합니다. 앱과 일자별 백테스트가 같은 분류 규칙과 추천엔진을 사용합니다.

이번 분석의 원천자료 기준일은 **2026-09-04**입니다. v2.15.7은 사용자 승인에 따른 배포 버전입니다. 코드 버전과 별개로 앱에 저장된 낙찰이력의 최종일을 확인해야 합니다. 기관별 실적을 포함한 분석 검토서와 상세 결과는 비공개 로컬 자료로 보관하며 공개 저장소에 포함하지 않습니다.

## 설치 및 실행

저장소 전체를 내려받고 해당 폴더에서 실행합니다. 현재 `runtime.txt`의 기준은 Python 3.12입니다. Windows 설치 시 Python을 PATH에 추가하면 아래 명령을 사용할 수 있습니다.

```text
pip install -r requirements.txt
streamlit run "입찰 앱.py"
```

필요 라이브러리는 Streamlit, pandas, numpy, openpyxl, xlrd, matplotlib이며, 세부 버전은 `requirements.txt`를 따릅니다. 로컬 실행 후 브라우저에서 `http://localhost:8501`에 접속합니다.

운영 실행파일과 Streamlit Main file path는 항상 **`입찰 앱.py`**로 유지합니다.

## 배포 구성과 관리자 설정

v2.15.7은 실행파일 하나만 교체해서는 동작하지 않습니다. 아래 파일을 같은 배포 버전으로 함께 반영해야 합니다.

| 파일 | 역할 |
|---|---|
| `입찰 앱.py` | Streamlit 화면, 이력 관리, Excel 출력 |
| `bid_rules.py` | 업종·모델군, 한전 입찰범위, 참여업체 수, 날짜 해석 |
| `bid_engine.py` | 사전 이력 정제와 공통 추천엔진 |
| `bid_legacy.py` | 기준 추천식과 기존 통계 계산 |
| `model_policy.json` | 검증 후 채택된 경로, 적용 시작일, 기준일이 있는 검증 요약 |
| `requirements.txt`, `runtime.txt` | 실행환경 |
| `pattern_stats.json` | 기존 패턴통계 리소스 |

기존 GitHub 저장소는 `jogeunho1105-droid/bid-strategy`, 운영 브랜치는 `main`입니다. Streamlit 설정의 Repository·Branch·Main file path가 해당 값과 일치하는지 확인합니다. 검토와 배포 승인을 받은 뒤 위 파일들을 함께 반영하고, 운영 화면의 버전·기준일·추천 결과를 확인합니다. 자동 반영이 지연되면 Streamlit 관리 화면에서 앱 재시작 후 다시 확인합니다.

관리자 비밀번호는 Streamlit Secrets에 설정합니다.

```toml
ADMIN_PWD = "운영용비밀번호"
```

로컬에서는 `.streamlit/secrets.toml`에 같은 항목을 설정할 수 있습니다. 비밀번호와 원본 낙찰데이터는 공개 저장소에 올리지 않습니다. 낙찰이력은 앱의 배포자 관리에서 별도로 업로드하며, 앱 재배포 후 저장 이력이 유지되는지도 확인합니다.

## 사용 방법

1. 사이드바의 **배포자 관리**에서 관리자 비밀번호를 입력하고 낙찰이력 `.xlsx` 또는 `.xls` 파일을 업로드합니다.
2. **투찰전략 분석**에서 나라장터 입찰서류함 `.xls` 또는 `.xlsx` 파일을 업로드합니다.
3. 공고별 중심모델군, 참여업체 수, 최종 추천 사정률, 추천기준금액, 산정 근거를 확인합니다.
4. 발주처 전체와 해당 모델군·세부업종의 흐름 차트를 비교합니다. 차트에도 해당 공고일 이전 이력만 표시합니다.
5. 업체별 추천표를 Excel로 내려받고, 개찰 후 `사후낙찰검증` 시트에 당사 실제 투찰정보와 결과를 기록합니다.

낙찰이력 업로드의 필수 열은 `개찰일`, `발주기관`, `공고명`, `기초금액`, `예가/기초(0%)`입니다. `공고번호`, `업종`, `지역`, `1순위사정율(0%)`도 함께 관리합니다. 1순위 사정율이 없으면 예가 예측용 이력에는 사용할 수 있어도 해당 공고의 가상 낙찰 여부는 판정할 수 없습니다.

`추천기준금액 = 기초금액 × (100 + 추천사정률) ÷ 100`입니다. 이 값은 낙찰하한율을 반영한 최종 투찰금액이 아닙니다.

## 중심모델군과 세부업종

| 중심모델군 | 내부 분류 |
|---|---|
| 일반 건설사업관리 | `construction_management` |
| 일반진단 | `diagnosis` |
| 설계 | `design` |
| 일반감리 | `supervision` |
| 한국전력공사감리 | `kepco_supervision` |
| 공동주택 및 주거시설 감리 | `residential_supervision` |

전기공사는 `electric_construction`으로 분리해 1개사 단일추천을 적용하며, 분류 근거가 없는 건은 `other`·미분류로 남깁니다. 일반진단 안에서도 VLF, PD·부분방전, 광학, 콘크리트, 초음파 등의 세부업종을 유지합니다.

공고명에 명시된 건설사업관리·감리·설계 업무를 우선 판별하고, 공고명만으로 부족하면 업종을 보완적으로 사용합니다. 아파트라는 단어만으로 설계·건설사업관리를 주거시설 감리로 바꾸지 않습니다. 콘크리트 시험실 설계는 설계, 초음파수위계 교체 전기공사는 전기공사로 구분합니다. 전력감리·전력설계 등 용역업종을 전기공사로 흡수하지 않습니다.

## 참여업체 수와 한전 이력 분리

| 공고 조건 | 당사 참여업체 수 |
|---|---:|
| 한전 부산울산 지역제한 감리·기초금액 1억원 미만 | 2개사 |
| 한전 부산울산 지역제한 감리·기초금액 1억원 이상 | 3개사 |
| 한전 경북·대구 지역제한 감리 | 1개사 |
| 한전 전국 감리 | 전국입찰 실적 보유 3개사 |
| 한전 VLF진단·기초금액 1억원 미만 | 2개사 |
| 한전 VLF진단·기초금액 1억원 이상 | 3개사 |
| 한전 기타진단 | 3개사 |
| 전기공사 | 1개사 |
| 그 외 공고 | 기존 지역별 참여구분과 3개사 기준 유지 |

정확히 100,000,000원인 경우는 1억원 이상에 포함합니다. 경북 소재 전국 감리 실적 미충족 2개사는 전국 감리 추천 대상에 포함하지 않습니다.

한전 감리의 추정가격은 `기초금액 ÷ 1.1`이며, 추정가격이 프로젝트 고시금액 기준보다 **작을 때** 지역제한으로 구분합니다. 같은 금액이면 전국입찰 쪽입니다. 금액 경계는 소수점 오차 없이 비교합니다.

| 적용연도 | 프로젝트 고시금액 기준 |
|---|---:|
| 2021~2022 | 2.1억원 |
| 2023~2024 | 2.2억원 |
| 2025~2026 | 2.3억원 |

한전 지역제한 감리에는 지역제한 이력만, 전국 감리에는 전국 이력만 사용합니다. 이력 분류는 모든 한전 본부에 같은 금액·연도 기준을 적용합니다.

부산울산·경북·대구 외 권역의 지역제한 공고는 기존의 업로드 제외 운영조건에 따라 **참여 성과 백테스트 대상에서 제외**하고, 같은 범위의 과거 흐름을 학습하는 이력으로는 보존합니다. 현재 앱에 타 권역 공고를 넣으면 기존 전국입찰 운영 가정이 적용될 수 있으므로 가정 경고와 공고의 지역제한을 확인해야 합니다. 가정이 있는 추천을 참가자격이 검증된 전국입찰 추천으로 해석하면 안 됩니다. 데이터만으로 당사의 모든 면허·실적·자격요건을 확인한 것은 아닙니다.

## 기준 추천과 대체 전략

기본 추천은 방향성 헷지·중심모델·라인 헷지입니다. 2개사 참여에는 방향성 헷지와 중심모델을, 1개사 참여에는 중심·단일 모델을 사용합니다. 한전 지역제한 1개사의 최근 3/5/10건 보정과 전기공사 전용 보정은 공통 엔진에서 한 번만 계산합니다.

| 방법 | 계산 목적 |
|---|---|
| 방향성 헷지 | 과거 부호 전이와 직전 흐름으로 중심값 밖의 방향성 보완 |
| 중심모델 | 기존 기관·세부업종 모형과 최근 흐름으로 중심 추천값 산정 |
| 라인 헷지 | 0.02%p 라인과 과거 패턴 뒤의 빈도에 따른 보완 |
| 기관·모델군 축소중심 | 같은 모델군의 최근 중심으로 기관 소표본의 과도한 변동을 완화하는 후보 |
| 낙찰구간 대체 | 과거 `예가/기초 < 추천 < 1순위` 구간을 이용해 중심·방향성·라인 중 한 자리의 추가 기여도를 높이는 후보 |

대체 전략은 후보를 계산했다는 이유만으로 적용하지 않습니다. 개발·후보검증·최종 재검증을 거쳐 채택된 경로만 `model_policy.json`에 기록합니다. 구간 대체는 다른 참여업체의 추천으로 이미 포괄한 과거 구간을 고려하며, 참여업체 수나 추천 개수를 늘리지 않습니다. 표본이 부족한 경우 기준 추천으로 돌아갑니다.

정책 적용 순서는 **발주기관+모델군+입찰범위 경로 → 모델군+입찰범위 경로 → 기준 방법**입니다. 정책에 없는 경로는 기준 추천을 유지합니다. `effective_from`은 자료 최종일 다음 날인 **2026-09-05**를 기준으로 기록하며, 그 날짜 이전 공고에는 새 정책을 소급 활성화하지 않습니다. 이 날짜는 정책의 계산상 적용 시작일이며 운영배포 완료일을 의미하지 않습니다.

화면과 Excel에는 실제 적용된 최종 추천값과 모델군·대체 전략 여부만 표시합니다. 후보 여러 개 중 실제 결과에 가장 가까웠던 값을 사후 선택해 운영 추천으로 제시하지 않습니다.

## 전기공사 단일추천

전기공사는 동일 발주기관, 확인 가능한 동일 지역, 금액구간, 최근 1년·90일 흐름을 반영하고 최근 관련 이력의 분위수로 과도한 보정을 제한합니다. 지역이 비어 있으면 `지역미상`으로 유지하고 동일지역 요소를 제외한 나머지 가중치를 재정규화합니다. 누락 지역끼리 같은 지역으로 간주해 학습하지 않습니다.

사전 추천 시점에 확정되지 않은 **대상 공고의 실제 경쟁업체 수**는 사용하지 않습니다. 현재 공유엔진은 실제 경쟁업체 수를 입력한 경로를 비활성화하여 백테스트와 앱의 사전 정보조건을 일치시켰습니다. 당사가 참여할 수 있는 1~3개 업체 수와 전체 경쟁업체 수는 서로 다른 항목입니다.

## 데이터 정제와 날짜별 백테스트

앱과 백테스트가 `bid_engine.prepare_history` 및 같은 추천엔진을 사용합니다.

- YY.MM.DD, 일반 연월일 문자열, Excel 날짜 일련번호를 해석하고 날짜 단위로 맞춥니다.
- 날짜·목표값·발주기관·공고명이 확인되는 유효 이력을 사용합니다. 목표값은 유한하고 절댓값 10%p 미만인 자료로 제한합니다.
- 완전히 동일한 행은 제거합니다. 공고번호가 있고 발주기관·개찰일·공고명·기초금액이 같은 반복 수집은 동일 개찰 사건으로 묶습니다. 차수·공구·개찰일이 다른 자료를 공고번호만으로 합치지 않습니다.
- 같은 사건에 서로 다른 예가/기초가 있으면 유리한 행을 선택하지 않고 해당 사건을 제외합니다. 1순위값만 충돌하면 판정값을 미상으로 처리합니다.
- 같은 사건의 반복 수집에서 확인된 1순위값·지역은 빈 값을 보완할 수 있습니다. 그 외 지역 누락을 임의로 추정하지 않습니다.
- **대상 공고일보다 이른 날짜에 확정된 결과**만 학습합니다. 같은 날짜의 결과는 그 날짜의 모든 예측을 만든 후 추가합니다. 앱에서는 입찰서류함의 투찰마감일, 과거 검증에서는 개찰일을 기준으로 이전 날짜만 사용합니다.
- 해당 공고의 실제 예가/기초, 1순위 사정율, 실제 경쟁업체 수는 예측 입력으로 사용하지 않습니다. 과거 공고에서 이미 확정된 1순위값만 구간모델 학습에 사용할 수 있습니다.
- 초기 이력 부족, 한전 범위 미확인, 운영상 참여대상 제외 건은 제외 사유와 건수를 별도로 기록합니다.

검증기간은 개발 `2025-08-31까지`, 후보검증 `2025-09-01~2026-05-31`, 최종 재검증 `2026-06-01~2026-09-04`로 구분합니다. 최종 구간은 과거 버전에서 이미 검토한 일부 자료와 겹치므로 완전히 처음 보는 자료라고 주장하지 않습니다. 최신 추가분은 별도 보조 집계합니다.

후보 선택은 선행 구간에서 고정하고, 최종 재검증에서 공고별 개선폭과 날짜 단위 재표집 신뢰구간·다중비교 보정을 확인합니다. 통과하지 못한 후보와 표본 부족 경로도 검토서에 기록합니다. 최종 결과를 본 뒤 살아남은 경로를 과거 전체에 다시 적용한 수치는 선택 절차의 독립 검증성과와 구분합니다.

## 가상 낙찰률의 판정과 분모

사용자가 지정한 기준은 다음과 같습니다.

`예가/기초(0%) < 추천사정율 < 1순위사정율(0%)`

- 공고별 실제 참여 가능한 업체 추천 중 하나라도 두 경계 **사이**에 있으면 그 공고를 가상 낙찰 1건으로 계산합니다.
- 경계와 같은 추천값은 미낙찰입니다.
- 유효한 숫자로 결과가 확인되면 1순위값과 예가/기초가 같거나 역전된 경우도 엄격 부등식상 **미낙찰**입니다. 유리한 양수 구간만 남겨 전체 낙찰률을 높이지 않습니다.
- 누락·비유한·범위 이상 결과값은 판정불가로 구분합니다. 주된 비율의 분모는 참여·이력 조건을 충족한 공고 중 결과를 판정할 수 있는 공고입니다.
- 양수 구간만의 조건부 비율은 비교용 별도 지표이며 전체 가상 낙찰률과 섞지 않습니다.
- 여러 추천값의 최소오차는 보유업체들의 커버 범위를 평가하는 지표입니다. 중심모델 한 값의 정확도나 낙찰확률과 같지 않습니다.

이는 실제 당사 참여기록을 집계한 낙찰률이 아니라 과거 공고에 사전 추천을 적용한 **가상 낙찰률**입니다. 당사 실제 성과는 참여 여부·실제 투찰값·무효/실격·최종결과를 누적하여 별도로 검증합니다.

Excel의 `사후낙찰검증` 시트도 같은 엄격 부등식을 적용합니다. 숫자 0은 정상 입력값이며 빈칸·문자 입력은 판정불가로 남깁니다. 1순위값이 예가/기초보다 작은 역전 구간은 주황색으로 표시하여 원본 확인 대상으로 구분합니다. 자세한 해석은 `검증기준` 시트에 있습니다.
